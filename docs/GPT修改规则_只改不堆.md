# 代码修改通用规则：只改不堆

适用于任何仓库、任何模型。直接整段粘进 GPT / Claude 的 system prompt、Custom Instructions 或项目 `AGENTS.md`。

解决的问题：模型被要求"对齐/重构/迁移/优化/适配"时，倾向于**新写一份**而不是**改掉旧的**。旧实现留在原地，新实现并排放着，两份都还能 import。跑几轮之后，同一个函数在仓库里有三个版本，没人知道哪个在执行。

---

## 短版（塞进 system prompt 的最小集）

> 改代码时你的默认动作是**修改已有代码**，不是新增并行代码。
> 动手前先 grep + 读现有实现；新增任何函数/字段/文件前，先证明它不存在。
> 搬迁 = 移动，必须在同一次改动里删掉源文件。
> 新增的配置项必须能给出"入口 → 解析 → 业务代码里真正读它的那一行"。
> 以对齐/重构/迁移/优化/清理/适配为名的改动，**删除行数不得为 0**。
> 交付时逐条输出：改了哪些已有代码、新增物替代了什么、被替代物是否已删、死引用 grep 结果（须为空）、`+X / −Y`、测试原始输出、未完成项。不许只回"已完成"。

## 完整版 R1–R8

### R1 先读后写

动手前先 grep 相关符号、读现有实现。禁止在没读过现有代码的情况下新增函数、类、模块或字段。

写完要能回答一句话：**"我改的是哪一处已有代码"**。若确实没有已有代码，先给出证明它不存在的检索结果，再新增。

### R2 禁止平行实现

不许用新开关、新参数、新标志开出第二条代码路径让新旧实现并存。需求变了就**改原路径本身**。

确需灰度并存时，必须在同一次回复里写明：旧路径的删除条件、删除时机，并把它列进未完成项。

> 典型反例：给函数加 `enhanced=True` 分支，新逻辑走 `if enhanced:`，旧逻辑原封不动留在 `else:`。半年后没人敢删，因为不知道还有谁传 `enhanced`。

### R3 搬迁是移动不是复制

把代码挪到新文件、新目录或新包，必须在**同一次改动**里删掉源文件。"先复制，稍后再删"一律视为未完成。

自查方式：同一个函数名或类名是否同时出现在两个文件里。

### R4 新增的东西必须有读取点

新增配置字段、环境变量、CLI 参数、UI 控件或结果字段，必须给出完整链路：

```
入口（表单 / CLI / env）
  → 解析（routes.py / argparse）
    → 配置对象（ExtractionConfig 之类）
      → 业务代码里真正读它的那一行  ← 必须指得出来
```

给不出最后一环就**不许加**。加了没人读的字段，等于在 UI 上放一个假开关。

### R5 替换后回扫死引用

改完 grep 被替换掉的旧函数名、旧字段、旧环境变量、旧模块路径，结果必须为空。

扫描范围不止 `src/`——`docs/`、`.env.example`、`tests/`、`README` 一起扫。旧变量名留在 `.env.example` 里，运维会照着配，然后发现不生效。

### R6 增删比自检

以"对齐、重构、迁移、优化、清理、适配"为名的改动，**删除行数不得为 0**。

若 diff 是纯增加，先自问："这次加的替代了什么？被替代的为什么还在？"答案写进交付说明。答不上来说明 R2 或 R3 违规了。

经验阈值：重构类改动 `+X/−Y` 中 `X/Y > 10` 就该停下来复查。

### R7 不扩大范围

只改任务点名的文件。不顺手格式化、不重排 import、不重命名、不补类型注解、不夹带顺便优化。

发现别的问题**单独列出来报告**，不要在同一个 diff 里解决——混在一起的改动没法 review，也没法回滚。

### R8 交付自检

每次改完必须逐条输出，缺一条视为未交付：

| # | 项 |
|---|---|
| ① | 修改的已有代码（`文件:函数`） |
| ② | 新增的代码，及其替代对象；被替代物是否已删 |
| ③ | 搬迁项的源文件是否已删 |
| ④ | 新增配置项的完整链路（R4 那四层） |
| ⑤ | 死引用 grep 的**命令与输出**（必须为空） |
| ⑥ | `+X / −Y`；若 `Y=0`，说明原因 |
| ⑦ | 测试命令的**最后 5 行原始输出** |
| ⑧ | 未做的与存疑的；没有就写"无" |

不许只回复"已完成""已优化""已对齐"。

## 七种典型堆积模式（照着认）

| # | 症状 | 根因 | 违反 |
|---|---|---|---|
| 1 | 同一模块在两个目录各一份，只差 import 行 | 复制进新包但没删原件 | R3 |
| 2 | `if enhanced:` / `if v2:` 分支，全仓库找不到传 `True` 的调用点 | 新旧并存后旧的没删 | R2 |
| 3 | UI 上的开关勾了没反应 | 字段传到底没人读 | R4 |
| 4 | `.env.example` 里的变量配了不生效 | 代码删了文档没跟 | R5 |
| 5 | `channels.py → a_channel.py → b_channel.py → core.py`，中间两层只做转发 | 每次重构都加一层 shim 兼容旧路径 | R2 |
| 6 | 测试文件 1500 行，大半在测已删除的机制 | 测试只加不删 | R6 |
| 7 | diff 是 `+2785 / −142`，提交信息写"重构" | 纯堆积 | R6 |

## 怎么验收模型有没有遵守

拿到交付后只看两个数：

1. **`git diff --stat` 的 `−Y`**。重构类改动 `Y=0` 直接打回。
2. **R8 第 ⑤ 项的 grep 输出**。不为空说明有死引用没扫干净；模型没贴命令说明没跑。

这两项过不了，其余描述再漂亮都不用看。
