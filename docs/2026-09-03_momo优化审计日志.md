### 2.3 `transport.py` 挂着一条永不执行的 590 行分支

**问题**：`5d1b2c0` 为 MoMo 在 `BrowserSentinelProvider` 里加了 `enhanced=True` 的第二套实现——同源 SDK 注入、cookie 桥、telemetry 桥、独立启动路径。等 MoMo 独立成包、改用 `_sentinel_runner.py` 起真实 Chrome 自己产证明后，这条分支就再没有执行过：**唯一构造点在 `DefaultTransportFactory.chatgpt` 的 GCash 分支，从不传 `enhanced`；全仓库无 `enhanced=True`**。

它不只是占地方——它和 GCash 的活代码交织在同一批方法里，读 `transport.py` 的人必须先分辨哪一半是死的。

**现在**：`grep -n "enhanced" payment_link_extractor/transport.py` 为空。1514 → 950 行。

删掉的 10 个方法及各自死因：

| 方法 | 死因 |
|---|---|
| `_build_sentinel_init_script` | 往浏览器注 Sentinel 桥的 init script；证明改由 `_sentinel_runner.py` 在真实 Chrome 146 里产 |
| `_enhanced_open_args` | 只为把 init-script 挂到 open URL 之后，随上一项失效 |
| `_set_cookie` | 只被 `_start_enhanced` 调用 |
| `_sync_pending_update_from_browser` | 方法体首行就是 `if not self.enhanced: return` |
| `_start_enhanced` | 125 行的 MoMo 专用启动路径 |
| `prepare` / `prepare_flow` / `_normalize_flow` | 全仓库零调用者 |
| `_store_ping_telemetry` / `_captured_ping_telemetry` | 只服务于 `headers` 里那段被删的 enhanced 块 |

收窄的分支：

| 位置 | 原来 | 现在 |
|---|---|---|
| 构造器签名 | `enhanced` / `session_token` / `timezone` 三参数 | 全删 |
| 构造器体 | `native_browser_ua` / `browser_headed` / `browser_profile` / `sentinel_init_script` 四属性 + 27 行 UA-Data 注入与落盘 | 全删 |
| `_base_command` | 4 段 `if` 判 `enhanced` 决定要不要挂 UA / headed / init-script / profile | 2 行无条件 `extend` |
| `_run` | `if self.enhanced: env["TZ"]=self.timezone else: env.setdefault(...)` | `env.setdefault("TZ", "Asia/Manila")` |
| `_start` | 开头三行 enhanced 短路 | 删 |
| `_ping` | enhanced 专用 `window.__opllSentinelReferer` 块 | 删，保留通用 `expression` |
| `headers` | 46 行 enhanced 块 | 删，保留 `self._ping(referer)` 之后全部 |

两处**只能局部删**（整删会打断 GCash），已逐字复核：

- **`_capture_bootstrap`**（现 `transport.py:638-651`）：只删 `if self._attestation or not self.enhanced: return` 之后的部分。前半段读 `#client-bootstrap` 取 `webDeploymentAttestation`，是 GCash 的 `_start` 在调。✅ 保留完好。
- **`_sync_cookies`**（现 `transport.py:652-672`）：`if not self.enhanced:` 那个分支（注释原文 *Preserve the original lightweight GCash behavior byte-for-byte*）**就是** GCash 唯一的 cookie 同步实现。做法是把该分支左移一级、删 `if` 行与尾部 `return`，再删掉整个 `momo_cookie_allowlist` / `momo_cookie_jar_mode` 段。✅ 现 20 行，方法内无 `enhanced` / `momo` 字样。

### 2.6 浏览器版本三处不一致 → `status=blocked`

**问题**：HTTP 侧 curl_cffi 用一个 profile、UA/client hints 用另一个、产 Sentinel 证明的浏览器又是系统 Chrome 的第三个版本。风控校验的正是这三者的一致性，混版本直接 `status=blocked`。而 `momo_fingerprint` 的"自动随机"还会在 136/145/146/150 之间轮换，把不一致做成常态。

**现在**：整条 MoMo 路径钉死单一 Chrome 146 身份，三件套同版本：

| 环节 | 位置 | 值 |
|---|---|---|
| TLS 指纹 | `momo/_transport.py` | `PAYMENT_BROWSER_IMPERSONATE = "chrome146"` |
| UA / client hints | `momo/_transport.py` | `Chrome/146.0.0.0`，`sec-ch-ua` 钉 146 |
| 产证明的浏览器 | `momo/_sentinel_runner.py` | `_locate_chrome146()` → 真实 headless Chrome 146 |

`_sentinel_runner.py` 把**真实启动的** `browser.version` 送进版本闸门，版本不对直接抛异常并给出安装命令，不再静默降级。轮换选项已随 `momo_fingerprint` 一并删除。

**前置条件状态**：已满足。`payment_link_extractor/runtime/chrome-146.0.7680.165/` 存在，`BROWSER_EXECUTABLE` 可定位。（Playwright 自带 Chromium 是 138，不装 146 内核 MoMo 一次都跑不起来。）
