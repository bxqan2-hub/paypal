# GoPay `78c1357` 优化解析与 PayPal 共享核心回退说明

## 结论

本次回退目标为提交 `7ec66b3`：GoPay 保留独立渠道注册和 `gopay_url` 结果字段，但提链协议重新调用 `paypal_channel.extract_legacy_payment_link`，并恢复 `uses_legacy_transport=True`。

优化分析以接入 Go 切片的 `50c3a45` 为起点，覆盖：

```text
50c3a45  dedicated GoPay core slice
    -> 22784eb  browser proof / checkout diagnostics
    -> 91089a3  HAR transport alignment
    -> 78c1357  browser session and proof hardening
```

`5314dcf`、`61bd309`、`3697637` 是 `78c1357` 之后的金额门禁提交，本说明不把它们计入“78c1357 优化总点”；本次回退会一并回到 `7ec66b3`，因此这些后续改动也会消失。

## 接入 Go 切片（`50c3a45`）

- 新增 `gopay_pro_core` Go 协议切片、来源清单和 SHA-256 完整性校验。
- GoPay 拥有独立 Python 核心入口、适配器和 `ID/IDR` 固定市场策略。
- GoPay CS 链路增加 Stripe init、Elements、渐进税区、税务快照、Payment Page、`pm_`、confirm、approve、轮询和 provider redirect 的协议参考实现。
- 增加独立 provider 主机白名单、独立 CookieJar、代理冷却、优惠探测和印尼虚构地址目录。

## `22784eb` 优化点

### Checkout 响应与重试

- 新增 `CheckoutCreateError`，把创建失败区分为 `unusual_activity`、`rate_limited`、`upstream_transient`、`access_token_invalid`、`access_denied`、`payment_method_unavailable` 等模式。
- 重试由错误的 `retryable` 字段控制，终止型 AT/权限错误不会被盲目重试。
- Web 任务记录 `failure_mode`、`retryable`、尝试次数和代理轮换状态。

### 支付方式合并

- 递归收集嵌套响应中的 `payment_method_types`、`custom_payment_methods` 和 `payment_methods`。
- 通过 `id/type/name/payment_method_type` 去重，同时合并重复对象字段，避免 CS/OAICS 响应层级差异导致 GoPay 被误判为不可用。

### 离线诊断

- 新增 `gopay_pro_core/validation.py`，可对脱敏样本统计 `oaics_`/`cs_`、成功率、支付方式和失败模式。
- 新增针对 Sentinel、重试、方法合并和批量验证的回归测试。

## `91089a3` 优化点

- Sentinel SDK 从 GCash 目录迁移到本站独立的 `payment_link_extractor/sentinel_assets`，解除渠道资源耦合。
- GoPay 默认客户端版本对齐 HAR：`oai-client-build-number=10012890`、对应 `oai-client-version`。
- `oai-language` 改为按 GoPay 国家配置生成 `id-ID`，并让 `Accept-Language` 使用 locale-first 顺序。
- Checkout telemetry 从静态 `[1,null]` 改为八项动态数组，保留环境变量覆盖。
- `.env.example` 不再把 `OPLL_OAI_LANGUAGE` 固定为 `en-US`。

## `78c1357` 相对 `91089a3` 的直接优化

### Sentinel 证明强制化

- `openai_sentinel_headers(..., required=True)` 在 GoPay 缺少浏览器 provider、证明生成失败或 token 为空时直接失败，不再静默降级到旧 token/无 token。
- Checkout 创建、CS taxes、OAICS confirm 对 GoPay 传入 `required=True`。

### 浏览器会话修复

- agent-browser 从 `about:blank` 改为真实 `https://chatgpt.com/` origin，确保 init-script、Storage 和 Sentinel SDK 在正确页面执行。
- 注入检查同时接受 `SentinelSDK.token` 和 `__proto2`，错误信息包含 agent-browser 输出。
- Sentinel token/observer token 生成后重新读取 HttpOnly Cookie，并同步 `oai-did` 到 HTTP 请求的 `oai-device-id`。

### 代理与 Cookie

- 认证 SOCKS5 浏览器流量改走本机 HTTP CONNECT bridge，HTTP 客户端仍使用原始代理。
- NextAuth session token 按 3800 字节拆分为 `.0/.1/...` Cookie，设置前清理旧 Cookie，避免超过 Chromium 4096 字节限制或拼接旧值。

### 资源与验证

- GoPay Sentinel init-script 使用本站独立资源路径，不再引用 `mk_gcash_open_source`。
- 增加 Cookie chunk、必需 Sentinel proof、真实 origin、设备 ID 同步等测试。
- 当时验证结果为 GoPay/Sentinel 相关测试 25 项通过，完整回归在后续修复提交中达到 182/185 项通过。

## 回退后的代码形态（`7ec66b3`）

回退后 [`gopay_channel.py`](../../../payment_link_extractor/gopay_channel.py) 仍是 GoPay 的独立注册入口，但函数内部调用：

```python
from .paypal_channel import extract_legacy_payment_link

return extract_legacy_payment_link(
    config,
    transport_factory=transport_factory,
    cancel_event=cancel_event,
    stage_callback=stage_callback,
)
```

[`paypal_channel.py`](../../../payment_link_extractor/paypal_channel.py) 的共享核心继续负责：Checkout 创建、优惠检查、Checkout Update、CS/OAICS Stripe 流程、支付确认和资源关闭；provider 配置仍通过 `gopay_url` 与 GoPay 主机列表区分结果。

回退后保留：

- GoPay UI 选项。
- `ID/IDR` 国家币种归一化。
- `gopay_url` 独立结果字段。
- PayPal 与 GoPay 的共享 legacy transport 标记。

回退后移除：

- `gopay_pro_core` Python/Go 专用运行入口和 Go 源码切片。
- GoPay 专用 Sentinel 强制证明、HAR 版本/telemetry、Cookie chunk 和 SOCKS5 浏览器桥接优化。
- GoPay 专用 Checkout 错误分类、方法递归合并、离线批量验证和相关测试。

## 后续修改约定

在共享核心状态下，GoPay 协议修改应优先进入 [`paypal_channel.py`](../../../payment_link_extractor/paypal_channel.py) 的公共逻辑，GoPay 特有差异只通过渠道注册表、provider 配置和结果字段表达；不要重新恢复对 `gopay_pro_core` 的运行时依赖，除非再次明确要求独立 GoPay 核心。
